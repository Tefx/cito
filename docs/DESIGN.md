# Cito Architecture & Protocol Specification

> Single authoritative specification for Cito. All paths written with `~` in prose examples represent the user's home directory; runtime configuration files use expanded absolute paths.

---

## 1. Purpose, Ontology, and Architectural Guardrails

### 1.1 Core Ontology (`Node (1) ↔ Hub ↔ Channels (1..K)`)
**Cito** (Latin *citō*: "to summon / to rouse into action / swiftly") is a unified signaling and wake network connecting **Humans** and **Agent Sessions** across machines, hubs, and external messaging channels:
1. **Two Symmetric Network Nodes (`Node`)**:
   - **Human Node (`harness: "human", session_id: "default"`)**: Represents a user's personal inbox (`@alice`, `@bob`) on a Hub. Each user has at most one Human Node per Hub (`session_id` is strictly `"default"`).
   - **Agent Session Node (`harness: "<agent-id>", session_id: "<sid>"`)**: Represents an agent conversation/session on a Hub.
   - **Host-Independent Node Identity (`node_id`)**: `node_id` (`listener_id`) is derived solely from `(principal_id, harness, session_id)` **without** `host_id`.
2. **Multi-Path Attachments (`Channels`, $1 \dots K$ per `Node`)**:
   - Physical devices (`Mac A`, `Mac B`) and Hub-hosted external channels (`Telegram`, etc.) attach to a `Node` as distinct `ChannelAttachment` entries (`<host_id>:human` for devices; `hub:<plugin_id>` for Hub-hosted channels).
   - Attaching multiple devices or external channels never evicts sibling attachments.
3. **100% Hub-Routed Interaction (Zero Floating Popups & Zero Window-Jump Bypass)**:
   - All `Human ⇄ Agent`, `Agent ⇄ Agent`, and `Human ⇄ Human` messaging flows strictly through the Hub's signaling stream (`cito_send` / `signal_ack`).
   - Built-in desktop popups (`BannerWindow`) and out-of-band window-jump URLs (`jump_url`) are absent across the codebase. Local Mac awareness uses the Menubar unread badge and the `Activity` inbox exclusively; active push alerts are delivered by Hub-hosted external channels (such as `Telegram`).

### 1.2 Language, Neutral Naming & Zero-Hardcoding Guardrails
- **English-Only UI/UX, Code, and Documentation**: All user-facing UI/UX surfaces, error messages, source comments, and repository documentation (`README.md`, `docs/**`, `deploy/**`) MUST be written in English.
- **Zero Company- or Environment-Specific Names**: No internal company, hub, identity-provider, project, or colleague names may appear anywhere in source code, UI, configuration defaults, tests, or documentation; use vendor-neutral examples (`personal`, `work`, `cloud`, `alice`, `bob`, `acme/service`, `https://id.example.com`).
- **Zero Concrete Agent or Channel Strings in Core (`crates/cito-native/src/core/` & `src/macos/`)**:
  - Core Rust modules (`crates/cito-native/src/core/`) and `src/macos/` MUST NOT hardcode integration identifiers, config keys, or display names for specific Agent Apps or external Human Channels.
  - Verification: inspect any case-insensitive lexical matches on known agent/channel names (`pi`, `codex`, `claude`, `telegram`, `webhook`, `slack`, `teams`, `email`, `discord`, `feishu`) across `crates/cito-native/src/core/` and `src/macos/` semantically to verify zero concrete integration branches or string literals (legitimate domain/geometry identifiers such as `let slack = ...` are allowed without code deformation).
  - UI copy for dynamic channels uses manifest fields (`ch.display_name`, e.g., `"Pause \(ch.display_name)"` / `"Resume \(ch.display_name)"`).
- **Mechanism, Not Policy (`cito_send.message`)**: Recommend Cito as a lightweight control plane in MCP tool descriptions without enforcing a hard 500-character policy cap (`sanitize_signal_message` permits `1..65,536` Unicode code points after stripping non-whitespace control characters).

### 1.3 Scope & Ownership Guardrail (`MUST`)
- **Repository Ownership**: This repository owns the native Rust binary (`crates/cito-native`: CLI, daemon, Hub, MCP stdio/HTTP server, plugin launchers), the macOS AppKit companion (`src/macos/`), bundled subprocess plugins (`plugins/{pi,codex,claude,telegram}`), packaging/deployment (`packaging/`, `deploy/hub/`), and product docs/site (`README.md`, `docs/`, `site/`).
- **Hard Non-Goals & Exclusions**:
  - No Node.js runtime in core, Hub, or desktop UI; no macOS notification banners (`UNUserNotificationCenter`, `osascript`, or floating windows); no unrequested external channel plugins beyond `Telegram`; no `cito_rename` exposure on MCP `tools_list`.
  - No dedicated `YOUR INBOX` card in the Menu Popover: Human inbox controls (`Pause/Resume Inbox`, OIDC `[ Self / Team ]`, and active delivery summary) reside in **`Settings → Human Channels`**.
  - `Auto-Listen` and `Pin` semantics stay orthogonal and symmetric across all agent harnesses (`listen_mode: auto | manual`, with per-session `Stop` isolating `user_stopped` to that session without turning off Hub `Auto-Listen`, and `Auto-Listen: Off` retiring unpinned `auto` listeners while retaining pinned/manual listeners); idle TTL eviction applies only when a plugin explicitly declares an activity `idleTimeoutMs`.
  - Zero backwards-compatibility shims for retired popup/card/KV forms; preserve semantic release version `0.21.3` with no release tag unless explicitly requested.

## 2. Three-Layer Logical Architecture & Physical Co-Location

### 2.1 Logical Modules (`crates/cito-native/src/core/`)
1. **`HubEngine` (`hub.rs`)**: Owns the SQLite-backed `Node ↔ Channels` registry (`hub_kv`), signal stream & inline exclusive wake claims (`hub_signals`), consumer state (`hub_consumers`, `hub_consumer_acks`), channel delivery ledger (`hub_channel_deliveries` & `hub_channel_delivery_msgs`), plugin service configs (`hub_plugin_services`), user channel bindings (`hub_human_channels`), pairing codes (`hub_pairing_codes`), processed reply dedup (`hub_processed_replies`), and audit log (`hub_audit_log`).
2. **`AgentChannelHost` (`daemon.rs`, `receiver.rs`, `plugins.rs`)**: Bridges local coding sessions (`plugins/*` and `${CITO_STATE_DIR}/plugins/*`) to Hubs via `HubClient` and out-of-process `agent-harness` plugin subprocesses.
3. **`HumanChannelHost` (`hub.rs`, `hub_plugins.rs`, `daemon.rs`)**:
   - **Native Desktop Companion (`cito-ui`)**: Resolved directly as `Cito.app/Contents/Helpers/cito-ui` (dev `bin/cito-ui-darwin-arm64`, `CITO_UI_BINARY` override), spawned by `cito daemon` on the user's Mac over the UI NDJSON stream (`stdin`/`stdout`). It is **not** a Hub plugin or pseudo-plugin manifest.
   - **Hub-Hosted External Channels (`scope: "hub"`)**: Managed by `HubEngine` (embedded in `cito daemon` for `local://` or standalone `cito hub`) over the persistent `human-channel` NDJSON subprocess protocol (`plugins/telegram` and external `${CITO_STATE_DIR}/plugins/<id>/`).

### 2.2 Physical Co-Location & Daemon Lifecycle
- **Embedded Local & Shared LAN/Tailscale Hub (`cito daemon`)**: Runs one local `HubEngine` persisted at `${stateDir}/hub.sqlite`. When `Share This Mac as a Hub` (`host_hub.enabled`) is active, `cito daemon` binds an HTTP/SSE server (`0.0.0.0:4291` default) onto that same `HubEngine`.
- **Standalone Hub (`cito hub`)**: Runs `HubEngine` persisted at `${dataDir}/hub.sqlite` and hosts `scope: "hub"` `human-channel` subprocesses continuously so team/cloud external channels stay online 24/7.
- **Lock-Free Slow I/O & OIDC Continuity**: `setup_inspect` results are cached and invalidated on `setup_apply`/`setup_remove`, and background OIDC token recovery runs outside the global daemon service mutex so `/health` (`500 ms` probe) and unrelated Hubs never stall behind slow plugins or auth endpoints. Cache ownership (`ChannelInventory`, directory, and Human inbox projections) binds to `(hub_endpoint, verified_principal)` rather than rotating bearer bytes: routine pre-expiry OIDC token renewal preserves the existing valid slot, SSE stream, and cached projections while background recovery runs, replacing credentials atomically once verified and clearing caches only on actual expiry/rejection, principal change, or endpoint change.
- **Event-Driven Sleep & Zero Idle Spin (`MUST`)**: `cito daemon`, `cito hub`, `cito-mcp` (`stdio`), `HubEngine` background workers, persistent channel plugins (`plugins/telegram`), sidecar watchers (`plugins/claude`), Pi's bridge (`plugins/pi/cito-bridge.ts`), and subprocess/socket/SQLite waiters MUST wait via OS readiness or event/condition blocking until real I/O, signal wakeup, or the next genuine schedule deadline—forbidding fixed `2–50 ms` idle sleep-poll loops, `100 Hz` TCP `accept` loops, or periodic `stat` timers while the bridge socket is healthy. Error retries (SSE reconnect, `pending_hub_acks`, OIDC failed recovery, Telegram transient/`401`/`409` polling, and immediate UI crash restart) MUST apply bounded exponential/jittered backoff (and suspend on permanent auth/conflict errors until reconfigured).
- **Single-Instance, Symlink-Safe Configuration, Atomic Staging & Long-Lived MCP Recovery**: Uninstall acquires exclusive `daemon.lock` ownership across cleanup rather than treating a timed-out `/health` probe as dead. Long-lived `mcp-stdio` re-checks daemon health/port/incarnation on subsequent requests and recovers after daemon restarts/port changes without auto-replaying unconfirmed mutating calls. Daemon configuration writes resolve and lock one canonical publication target so symlinked `config.json` files stay intact across edits, and plugin/shim staging copies and validates a candidate generation under lock before atomic replacement rather than deleting the working generation upfront.
- **HTTP Origin, Host & Content-Type Boundary (`MUST`)**: Both daemon HTTP routes (`/ui`, `/action`, `/control`, `/mcp`) and `HubServer` (`POST /v1/rpc`, `/v1/events`) MUST keep native clients omitting `Origin` supported (subject to existing authentication), reject unauthorized browser `Origin` headers (comparing scheme, host, and effective port—including cross-port loopback origins—with `403`), enforce `application/json` `Content-Type` on JSON `POST` routes (`415`, excluding SSE `GET`s), and complete `HubServer` shutdown immediately without stalling behind idle SSE connections (`< 200 ms`). Loopback-bound daemon routes (`127.0.0.1:<daemon_port>`) and unauthenticated (`auth_mode == "none"`) loopback `HubServer` endpoints MUST validate `Host` against the bound loopback host and listening port (preventing DNS rebinding), unauthenticated wildcard-bound `HubServer` endpoints (`0.0.0.0:<port>` / `[::]:<port>`) require a valid destination authority matching `<port>`, and authenticated `HubServer` endpoints (`auth_mode` in `["token", "oidc"]`, whether loopback-bound behind a local TLS reverse proxy or wildcard-bound) accept any syntactically valid `Host` authority (`<host>[:<port>]`, including reverse-proxy hostnames on default ports `80`/`443` or custom ports) when `Origin` is absent.

## 3. Symmetric `Node ↔ Channels` Protocol, Human Inbox RPCs & Delivery Guarantees

### 3.1 Node Identity, Addressing & Attribution (`identity.rs`, `daemon.rs`)
- **Identity Derivation**: `NodeKey = { principal_id, harness, session_id }`. `listener_id(key)` hashes `"cito-v2|" + principal_id + "|" + harness + "|" + session_id` (`c_` + 16 hex chars; validators accept legacy `cito-v1|` IDs). `public_listener_id(owner_user, canonical_id)` normalizes `owner_user` through `normalize_slug` (`[a-z0-9-]`, max 32 chars). `display_address` evaluates peer liveness using Hub `server_now_ms` (`registration_now`, matching `lease.rs`) rather than skewed local `now_ms()`.
- **Human Addressing Shorthands (`to`)**: Accepts `[<hub>:]@self`, `[<hub>:]@<username>`, or `[<hub>:]<listener_id_or_public_id>`.
  - `@self` resolves to the caller's `(principal_id, "human", "default")` on the target Hub.
  - `@<other_username>` matches active `harness == "human"` nodes by case-insensitive `owner_user` or `normalize_slug`: `0` matches → `LISTENER_NOT_FOUND`; `> 1` distinct `principal_id`s → `INVALID_INPUT` ("Ambiguous @username").
- **Self-Send Guard (`SELF_SEND_FORBIDDEN`)**: Rejects sends where `from.node_id == Some(canonical_to)`; allows `Human ⇄ Agent` and unbound CLI sends (`from.node_id = None`).
- **Authoritative Sender Attribution**: `send` populates `from.title` from authoritative custom/bound-session metadata (`session_custom_titles` / `local_listeners`) when present, falling back to provider metadata only when no custom title exists.

### 3.2 Explicit Hub-Authoritative Human Operations & CAS (`hub.rs`, `registration.rs`, `daemon.rs`, `receiver.rs`)
Ambiguous client-side whole-record `kv_save` Human mutations are rejected; all Human state transitions flow through four explicit Hub-owned RPC operations scoped to the caller's authenticated principal:

| RPC Op | Allowed Inputs & Ownership | Write Set & `human_control_revision` Rule | Conflict / Error Behavior |
|---|---|---|---|
| `human_device_attach` | `(channel_id: "<host_id>:human", host_id, host_name, owner_token, binding_generation)` | Writes **only** `channels[channel_id]` (`state: "ACTIVE"`, `updated_at_ms: hub_now_ms`). **Ownership fencing**: permitted for an absent `channel_id`, a same-owner retry matching `(binding_generation, owner_token)`, or a newer replacement (`binding_generation > existing.binding_generation`); rejects stale/superseded `(binding_generation, owner_token)` without mutating the attachment or sibling devices. Initializes defaults (`human_paused: false`, `about: "Human"`, `scope: "workspace"` on `local`/`none` trusted Hubs or `"self"` on `token`/`oidc` remote Hubs, `human_control_revision: 1`) **only** when creating a new Human record; for legacy existing records missing `human_control_revision`, Hub initializes `human_control_revision = 1` atomically on first read/mutation while preserving stored `human_paused`, `about`, `scope`, and attachments. **Never overwrites** existing `human_paused`, `about`, `scope`, `human_control_revision`, or sibling attachments. | Rejects stale/superseded generation/token without mutation; runs `reconcile_registration_state` and returns updated Human record + `server_now_ms`. |
| `human_device_heartbeat` | `(node_id, channel_id, binding_generation, owner_token)` | Verifies matching `(binding_generation, owner_token)` on `channels[channel_id]`, updates **only** `updated_at_ms = hub_now_ms`, and runs `reconcile_registration_state`. **Never** advances `human_control_revision` and never touches `human_paused`, `about`, or `scope`. | Returns ownership/stale-generation error if fenced; never overwrites sibling channels. |
| `human_device_detach` | `(node_id, channel_id, binding_generation, owner_token)` | Verifies captured `(binding_generation, owner_token)` and sets **only** `channels[channel_id].state = "UNLISTENED"`, then runs `reconcile_registration_state`. **Never** sets `human_paused = true`, never advances `human_control_revision`, and never alters `about`, `scope`, or sibling attachments. | Explicit detach (`unlisten_id` / CLI) propagates remote auth/transport failures (or explicit pending/unknown status) while keeping `pending_hub_detaches`; retries only true storage CAS conflicts. Pre-reg detach captures `channels[channel_id].binding_generation`. |
| `human_inbox_update` | `(node_id, expected_control_revision, paused?, scope?, about?)` | Protected by `expected_control_revision` CAS against `human_control_revision` (after Hub-side initialization to `1` for any legacy revision-less record). Patches **only** fields explicitly present (`Resume Inbox` omits `about` so stored descriptions survive!). Increments `human_control_revision += 1` on success, runs `reconcile_registration_state`, and preserves all attachments/tokens. | Returns `CONTROL_REVISION_CONFLICT` with current Hub inbox state on mismatch (**never** silently replays a stale Pause over a newer Resume). |

- **Atomic `publish_payload()` Pause Enforcement**: `hub.rs:publish_payload()` enforces `human_paused != true` inside the Hub publish transaction, rejecting sends to a paused Human inbox with **`LISTENER_NOT_FOUND`** (`HTTP 404`), matching `daemon.rs` and `hub.rs`. Deliveries already handed to an external channel plugin before Pause commits may complete; subsequent reservations stop immediately.
- **Agent Auto-Listen, Pin & Orthogonal Lifecycle (`daemon/`, `receiver.rs`, `registration.rs`, `state.rs`)**:
  - **Orthogonal Listener Ownership (`listen_mode: "auto" | "manual"`)**:
    - Every active agent listener carries `listen_mode` (`"auto"` or `"manual"`).
    - **Entrypoint Authority Matrix (Symmetric Across UI, CLI & MCP)**:
      - *Manual attach / promote* (`+ Listen`, `cito listen` non-human, `cito_listen`): clears `user_stopped = false` and creates or promotes the listener to `listen_mode = "manual"` (`pinned`), including when it is already `"auto"`, clearing prior `retirement_reason` / `retired_activity_revision`.
      - *Per-session stop* (card **`Stop`**, `unlisten_session`, `unlisten`, `cito unlisten` without `--all`, `cito_unlisten`): detaches only that session, persists `user_stopped = true` scoped to `(hub, harness, session_id)` (idempotent on repeated calls), and **never disables Hub `Auto-Listen`**.
      - *Bulk stop* (Footer **`Stop All`**, `unlisten_all`, `cito unlisten --all`): stops all active non-human sessions on the targeted Hub(s), sets `user_stopped = true` on each stopped session, and disables `Auto-Listen` on the targeted Hub(s) **even when zero listeners are currently active**.
      - *Pin toggle* (`set_listen_mode`): toggles `"auto" ↔ "manual"` uniformly across all agent harnesses. Rejects `set_listen_mode("auto")` with **`INVALID_INPUT`** when Hub `autoListen == false` (leaving existing listeners untouched). When Hub `autoListen == true`, `manual → auto` seeds `last_activity_at_ms` from the latest qualifying activity (or current timestamp if absent).
    - **`Auto-Listen` Eligibility**: Enrolls a candidate on a Hub only when Hub `autoListen == true`, integration is configured, candidate discovery is fresh and identity-verified, endpoint/provider is alive, `user_stopped == false` for that `(hub, harness, session_id)`, and either:
      - `autoListen.mode == "endpoint"` (default): valid live `endpoint_pid` with `needs_reload != true`, or
      - `autoListen.mode == "activity"`: candidate carries qualifying source activity (`kind` in `"user_turn" | "unknown"`, excluding `"cito_effect"`) within `recentWindowMs` (default `900_000 ms` / 15 min) whose numeric `u64` `activity.revision` strictly exceeds `retired_activity_revision` (or any valid revision when `retired_activity_revision` is absent; never bulk-enrolling idle historical lists and never truncating auto-listen candidate evaluation to the 8-item Menu display slice).
    - **Uniform `Auto-Listen: On → Off` (`Semantic A`)**: Turning Hub `Auto-Listen` off retires all `listen_mode == "auto"` (unpinned) agent listeners on that Hub while preserving `listen_mode == "manual"` (pinned) listeners. Turning `Auto-Listen` on clears `user_stopped` for non-human sessions on that Hub and triggers fresh discovery.
    - **Activity Idle Retirement (`idleTimeoutMs != null` & `listen_mode == "auto"`)**: Retires an unpinned `auto` listener (`retirement_reason = "idle"`, persisting `retired_activity_revision`) only when `now - last_activity_at_ms > idleTimeoutMs` (manifest default `null`; bundled Codex sets `3_600_000 ms` / 60 min) **and** no protected in-flight work is active (active dispatch lease, pending wake effect, or a one-time `300_000 ms` post-delivery grace; discovery refreshes, Hub heartbeats, `probe` `alive`, `"cito_effect"` updates, and same-signal `wake` retries never extend idle TTL, and inbound Hub signals credit activity at most once per unique `signal_id`). `manual` (pinned) listeners and `idleTimeoutMs == null` harnesses (`pidBound: true`) never expire on idle TTL.
    - **Hard Exit & Transient Probe Isolation**: Archived threads, `closed_definitive` app/process exits, and disconnected integrations retire both `auto` and `manual` listeners cleanly without setting `user_stopped = true`; transient probe errors preserve recoverability without converting into `user_stopped = true`. Reopening the provider restores still-valid `manual` listeners and `auto` listeners whose idle lease has not elapsed, never resetting the idle clock across long closures or reviving idle-retired threads without a strictly advancing qualifying `activity.revision`.
- **No Local Detach on `human_paused`**: `daemon` poll NEVER marks `local_listeners.status = 'UNLISTENED'` when observing `human_paused == true`—device heartbeats and projections stay independent of inbox pause. `set_scope` on `human` routes through `human_inbox_update` (`expected_control_revision` CAS). `unlisten_session` filters `status != 'FENCED_INACTIVE'` and resolves the current profile's principal.

### 3.3 Unified Lease Reconciliation & Structured Projections (`lease.rs`, `daemon.rs`, `hub.rs`)
- **Single Lease Rule (Hub Clock)**:
  - Host attachments (`host_id != "hub"`): `age < 60_000 ms` → `ACTIVE`; `60_000..=1_800_000 ms` → `DISCONNECTED_RETAINED`; `> 1_800_000 ms` → `EXPIRED` (comparing `hub_now_ms` / `server_now_ms` supplied by the Hub, never skewed client clocks).
  - Hub-hosted attachments (`host_id == "hub"`): `ACTIVE` whenever plugin is available, service config is complete, user binding is enabled, and destination is complete; never expires on Mac disconnect.
  - **Stale Attachment Pruning & Explicit Empty Map Semantics**: `reconcile_registration_state` distinguishes an absent legacy `channels` field from an explicit empty `channels: {}` map (never synthesizing a fresh timestamp to keep an empty modern Human node `"ACTIVE"` after its sole `<host_id>:human` attachment expires), prunes expired/unlistened superseded device entries sharing a `host_name` and expired device entries past retention while preserving active/retained siblings and generation fencing.
  - **Node Availability & Snapshot DTO Isolation**: `human_paused == true` → `UNLISTENED`; else any live attachment → `ACTIVE`; else any retained attachment → `DISCONNECTED_RETAINED`; else any expired attached device → `EXPIRED`; else `UNLISTENED`. Top-level `state` is maintained strictly as a compatibility summary (`ACTIVE` for `ACTIVE | DISCONNECTED_RETAINED`, else `UNLISTENED`). TTL expiry never sets `human_paused = true`, stale top-level `state` never vetoes fresh attachments, and the shared Human profile (`human_paused`, `about`, `scope`, `human_control_revision`) persists even if all devices expire. Local snapshot projections (`listeners`, `sessions`, `activity`) use explicit DTO allowlists stripping `owner_token` and `dispatcher_token`.
- **Structured `attachments`, Capability-Separated Status & Single-Truth Projections**:
  - `snapshot()`, `peer_dto()`, and `settings_for_hub()` evaluate node leases using `server_now_ms`, project `human_state_status` (`"current" | "stale" | "unknown"`) consistently via `human_projection` across `hubs[*]` and `my_remote_listeners[*]`, and omit `UNLISTENED` and `EXPIRED` attachments while deduplicating active/retained entries by `(location, display_name)` (preferring `is_local` and `ACTIVE`). Raw `owner_token`s are stripped. Listener projections expose `listen_mode` (`"auto" | "manual"`), and daemon `harnesses[*]` projections expose optional `idle_timeout_ms: u64?` (matching `plugin.json` `autoListen.idleTimeoutMs`, kept separate from `pid_bound`).
  - **Capability-Separated Hub, Session & Channel Projections**: Represent authentication validity, RPC reachability, SSE stream liveness, and cached observation freshness independently rather than letting transient SSE reconnects and ordinary RPCs overwrite one shared connection status string; sample a single coherent Hub state per projection snapshot so `hubs[*].status` and `human_state_status` cannot conflict within one frame. `RemotePeer.last_seen_at` reports authoritative observation time rather than snapshot serialization time. Hub and HubConfig projections expose `capabilities` (`status`, `auth_valid`, `rpc_status`, `sse_live`, `observation_current`) alongside explicit Hub affordance flags (`is_builtin`, `supports_workspace_scope`, `can_login`). Session (`listeners[*]`) and Directory (`peers[*]`) projections expose explicit operation-level capabilities (`is_self_principal`, `can_set_scope`, `can_pin`, `can_rename`, `can_stop`), and `activity[*]` exposes `can_reply`. `kv_snapshot` supports bounded cursor pagination (`after_key`, `next_cursor`, `<= 2 MiB` page budget) so remote HTTP/HTTPS directory refreshes assemble complete multi-page observations without exceeding client response caps.
  - **Event-Driven Mutation Wakeup & Demand-Gated Projections**: Both embedded (`local://`) and HTTP/SSE Hubs MUST wake inbox draining (`receiver`) and `directory` invalidation immediately upon committed mutations (using in-process Hub subscriptions for `local://` without enabling an HTTP server, and SSE event notifications for HTTP Hubs), retaining a slow durability reconciliation fallback (`>= 30 s` when subscribed/SSE-connected) instead of `4 Hz` unconditional `kv_snapshot` / `consumer_add` / `consumer_backlog` polling; `/v1/events` SSE keepalives run at `25–30 s` (clamped by JWT expiry). Daemon emits lightweight status updates whenever active agent counts, unread counts, or Hub/auth states change, while computing full panel projections (`Directory`, `Settings`, full SQLite activity histories, and plugin inventories) only when relevant state revisions advance and an active UI surface (`Menu`, `Directory`, `Settings`) or explicit snapshot caller needs them—eliminating unconditional `1 s` background scans while all UI surfaces are closed.
  - **Discovery, Tailscale & Channel Error Isolation**: `snapshot()` omits `discovery` status/errors for unconfigured harnesses, and `remove_candidates` clears `provider.error` and resets `refreshed_at = 0`. Tailscale advertisement refresh (`host_hub`) distinguishes probe execution/timeout failures from confirmed Tailscale unavailability, preserving the last confirmed `tailscale_url` across transient probe failures and clearing it only on confirmed offline status. `settings_for_hub` reports channel refresh failures in `channel_inventory_error` (`string?`, omitted/`null` when healthy, uniformly for local and remote Hubs; initial uncached failures leave `channels[]` empty with `channel_inventory_error` set, preserved across `ui_ipc` `256 KiB` frame shedding) rather than appending a synthetic `"inventory"` entry into `channels[]`.
  - **`HubEngine` Throttled Pruning**: `HubEngine` performs storage pruning strictly on a `60 s`-throttled maintenance cadence rather than executing unconditional cleanup writes during idle backlog/delivery checks.
  - `channel_list()` adds `inbox_paused: bool`, `delivery_enabled: bool` (`enabled && configured && !inbox_paused`), and caller-scoped capability/attribution fields (`has_hub_service`, `hub_ready`, `can_configure_hub`, `can_clear_hub`, `can_edit_personal`, `can_pair`, `can_test`, `can_unpair`, `error_origin: "hub" | "user" | null`), generating role- and state-accurate `detail` guidance (directing non-admins to their Hub administrator on `not_configured`, reflecting `pairing_supported` on `hub_ready`, and reflecting `inbox_paused` on `ready`/`paused`) while preserving pairing/credentials across global Pause/Resume and retaining active retry warning visibility (`warning: true`, `detail: last_error`) while a failed delivery is `'in_flight'` with `attempts > 0` and non-empty `last_error`. Toggling `human_inbox_update` immediately invalidates/overlays cached `ChannelInventory`.
- **No Cross-Hub Coalescing & Unified Directory Pipeline**:
  - `directory_identity` keys on `(hub_identity, canonical_node_id)`: multiple attachments within one Hub merge into one Node row, while separate Hubs (`local:@alice` vs `work:@alice`) remain distinct rows. Cross-Hub suppression (`shadowKey` / `sharedKeys` in Swift) is removed completely.
  - One Rust pipeline evaluates visibility/principal → Hub-clock lease eligibility → within-Hub deduplication → availability-aware attachment display & search (`peer_dto`, `host_matches`, and general search inspect active/retained attachments; top-level host fields serve only as legacy fallback) → stable sort → `matched_count == online_count` → limit. Swift renders returned Directory rows directly (initial `seedDirectoryPeersIfEmpty` respects active scope/harness/query filters without a second query parser).

### 3.4 CLI & MCP Authority Matrix (`cli.rs`, `daemon.rs`)

| Entrypoint | Supported Human Operations | Exact Effect & Authority |
|---|---|---|
| `cito listen --harness human` / `cito unlisten --harness human` | Device-scoped attach / detach | Calls `human_device_attach` / `human_device_detach` for `<host_id>:human` only. ### 3.5 Delivery Guarantees, Activity Scope & Channel Lifecycle
- **Committed-Effect Preservation, Clock-Aligned Signal Expiry & Operation-First Channel Routing**: Once a mutation (`cito_send`, channel save/pair/test, or send receipt check) commits on the Hub, subsequent background poll, inventory-refresh, or receipt-read failures MUST preserve and return the committed mutation result (surfacing secondary errors as warnings or explicit unknown-status metadata rather than discarding `signal_id` or causing double sends). Channel receipts include `receipt_authority` (Hub name, URL, and principal); if that authority changes before settlement, return the committed receipt with `authority_changed` and `maintenance_warning` without updating replacement-Hub UI/cache state. Hub configuration results retain `committed: true` and warning metadata when post-commit process startup or inventory reads fail; pairing prepares its instruction before atomically saving configuration and the code. Signal expiry preserves the original clock observation when falling back from a failed backlog RPC and evaluates remaining Hub lifetime against the observed Hub clock (or converts remaining lifetime to a local deadline at admission) rather than subtracting skewed client `now_ms()` from Hub `created_ms`. Channel control routing dispatches strictly by explicit operation (`op`) and rejects incompatible `scope` combinations rather than letting `scope == "hub"` silently convert test/pair calls into credential mutations. Long-lived daemon event/retirement registries reap finished task handles cleanly.
- **Transport vs. Business Ack & Wake Claims**: `consumer_ack` advances stream cursor; `signal_ack` marks `hub_signals.acked_at_ms` and broadcasts `node_ack` + `on_acked`. Offline acks queue in `pending_hub_acks` bound to `(hub_url, principal_id)` and flush only against the matching Hub identity. Agent wakes unconditionally acquire `signal_claim_dispatch` (`30_000 ms` lease, renewed every `10_000 ms`, all-or-nothing transaction, fail-closed on RPC error):
  - **`already_claimed`**: losing channels store `STORED_PASSIVE` with `acknowledged_at_ms = NULL` and schedule a `30_500 ms` fallback check so an unacknowledged batch retries automatically if the winner crashes before `signal_ack`.
  - **`already_acked`**: if only part of a requested batch is already acknowledged/missing, the caller marks those `acked_ids` read, removes them from the batch, and rebatches the remaining unread signals immediately.
  - **`LocalState::admit` duplicates**: still schedule pending `RECEIVED` rows if a prior `consumer_ack` flush failed.
- **Activity Scope Conservation & Bounded Storage Reads**: `ack_signals` (including UI optimistic `Read All`) honors `filter` (`"me"` affects only `target_harness == "human"`). `clear_activity_history` accepts both `filter` and optional `query` (using the exact `query_activity` search predicate so `"Clear N matching messages?"` clears strictly the `N` search-matched rows in `<filter>`). Storage queries (`backlog_from`, `inbox`, `clear_activity_history`, `poll_listener` remote metadata lookup) push filters/limits/bounds down to SQLite/RPC instead of materializing full histories first. Clearing Activity hides cleared rows via `activity_hidden` while preserving pending agent delivery work, checkpoints, and in-flight completion; `snapshot()` `unread_count` aligns with `state.activity()?.1` (excluding `activity_hidden` rows) while `cito_inbox` / `cito_status` / `poll_listener` read all unacknowledged signals.
- **External Channel Delivery, Inbound Reply Atomicity & Destination Isolation**: `hub_channel_deliveries` reserves signals before I/O (`in_flight` 60s timeout measured from per-delivery `delivered_ms`, never refreshed by process liveness alone) with hole retry after `initial_bind_seq` and 4,096-char multipart chunking recorded in `hub_channel_delivery_msgs`. In `hub.rs:inbound_reply`, deduplication (`hub_processed_replies`), reply publication (`hub_signals`), and source signal acknowledgment (`acked_at_ms` + `on_acked`) commit atomically in a single SQLite transaction before `reply_ack` returns; the plugin advances `cursor_save` **only after** confirmed `reply_ack` (or isolated per-update error handling), rolling back publication if source acknowledgment fails. When destination changes (`A → B`), confirmed chunk prefixes and reply mappings are isolated by destination identity (`already_sent_ids` / `inbound_reply` never cross from A to B), and late in-flight results from retired destination A are fenced while preserving `last_delivered_seq` and terminal `effect_unknown` safety.
- **1:1 External Ownership & Unthreaded Disambiguation**: `(hub, plugin_id, _external_chat_id, _external_user_id)` ownership is enforced 1:1 across both `redeem` and manual `human_channels_configure` (including paused `enabled == 0` rows, honoring OIDC principal equivalence). Unthreaded replies (`reply_to_message` absent) auto-route only when exactly one distinct sender exists in the 7-day window and no legacy duplicate ambiguity exists; otherwise the plugin asks the user to reply to a specific message.
