Protocol & System Design

Architecture & Protocol

Cito models every human user and every coding agent session as a symmetric participant on the same Hub network: Node (1) ↔ Hub ↔ Channels (1..K).

1. Symmetric Node (Human | Agent) ↔ Hub ↔ Channels (1..K) Ontology

  • Node (Logical Addressable Participant):
    • Agent Session Node: A specific coding agent session (for example, a Codex thread, a Pi session, or a Claude Code session), identified by (principal_id, harness, session_id).
    • Human Node: A human user on the Hub, identified by (principal_id, harness: "human", session_id: "default").
  • Channel ($1 \dots K$ Attached Endpoints per Node):
    • A Node is not locked to a single host or single window. A user's Human Node can have multiple attached Channels simultaneously—such as cito-ui on a MacBook Pro, cito-ui on a Mac Studio, and Telegram on a phone—without cross-host FENCED_INACTIVE eviction.
  • Pure Hub-Routed Interaction: All Human ⇄ Agent, Agent ⇄ Agent, and Human ⇄ Human communication flows through the Hub's signaling pipeline (cito_send / signal_ack).

2. Node Identity & @self / @<username> Addressing

Because NodeKey = (principal_id, harness, session_id) omits host_id, each user has a deterministic Human Node per Hub alongside their active Agent Session Nodes. In cito_send, callers can target:

  • to: "@self" (or "<hub>:@self"): Resolves in $O(1)$ to the caller's own enrolled Human Node on that Hub.
  • to: "@<username>" (or "<hub>:@<username>"): Resolves to that user's visible Human Node on the Hub (respecting self vs. workspace visibility scope).
  • to: "<listener_id>" (or "<hub>:<listener_id>"): Targets a specific Agent Session Node or Human Node directly.

3. Multi-Channel Read Sync & Single-Execution Wake

Cito separates transport stream delivery from business read acknowledgment so multi-device channels stay synchronized:

  • Stream Transport Cursor (consumer_ack): Advances when a daemon receives a signal over SSE so passively observed notifications are stored locally as unread (STORED_PASSIVE) without prematurely marking them read on other devices.
  • Business Read Acknowledgment (signal_ack): Emitted only when an agent drains its inbox (cito_inbox) or a human reads/replies in DirectoryPanel or Telegram. The Hub broadcasts a signal_acked event so all other attached channels clear their unread badges immediately.
  • Atomic signal_claim_dispatch: For wake_exclusive agent channels, the Hub atomically claims each signal sequence before wake execution so a session is woken at most once even if multiple daemons observe the stream.

4. Three-Layer Logical Architecture

  1. Layer 1 — HubEngine (crates/cito-native/src/core/hub.rs): Single-authority node registry, signal stream, read-state tracking, and OIDC/token row-level security. Runs identically in-process for standalone single-Mac use (url: "local://") and over HTTP/SSE in cito hub.
  2. Layer 2 — AgentChannelHost (crates/cito-native/src/core/daemon.rs, crates/cito-native/src/core/plugins.rs, plugins/*/native.rs): Local daemon, Rust hot-path stdio/hook binary, and agent harness plugins.
  3. Layer 3 — HumanChannelHost (src/macos/cito-ui.swift, plugins/human, plugins/telegram): Four-surface native macOS UI (cardMenu, DirectoryPanel with Directory | Activity + inline ComposerBar, 3-tab SettingsPanel, and WakeBanner) plus external human messaging plugins.

5. The 5 MCP Tools

Tool Parameters Behavior
cito_listen { about, tag?, hub?, scope? } Enrolls the calling session on the default or specified Hub with "self" or "workspace" visibility.
cito_unlisten { hub? } Revokes listening for the calling session on one Hub or all active Hubs.
cito_find { query?, hub?, user?, host?, harness?, repo?, limit? } Searches active visible Nodes (both Agent Session Nodes and Human Nodes) across connected Hubs.
cito_send { to, hub?, message, in_reply_to?, idempotency_key? } Sends a signal (1..65,536 Unicode codepoints) to @self, @<username>, or a target Node ID.
cito_inbox { hub?, ack_ids?, ack_all? } Reads unread signals for the calling Node and emits signal_ack when acknowledged.
