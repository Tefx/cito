Subprocess Plugin Authoring Guide

Cito launches agent harness and human channel integrations as subprocesses. A declarative plugin.json supplies the executable command, UI metadata, and configuration fields. Implement the protocol in any language; no in-process adapter or external SDK package is required. Write one JSON object per line to stdout, read requests from stdin, and send diagnostic logs to stderr.

1. Plugin Discovery & Manifests

On your Mac, install custom plugins under ${CITO_STATE_DIR}/plugins/<id>/ (default ~/.cito/plugins/<id>/) or in colon-separated directories listed in CITO_PLUGIN_PATH. On a standalone cito hub server, install channel plugins under <data-dir>/plugins/<id>/ or CITO_PLUGIN_DIR, with later roots overriding earlier manifests of the same ID.

  • id: ^[a-z0-9][a-z0-9_-]{0,31}$; external plugin directory names must match the ID. displayName must be non-empty.
  • kind: agent-harness or human-channel (the shorthand values agent and human normalize to those names).
  • tier: stable or experimental (default stable).
  • command: a non-empty array of [executable, ...args]. Executables starting with ./ or ../ resolve relative to the plugin directory.
  • sfSymbol, tint, and cliFlag control presentation and CLI enrollment. scope defaults to hub; fields and pairing declare configuration and account binding.

External plugins that omit command can provide an index.js entrypoint (or index.ts with Node's --experimental-strip-types) when a local Node runtime is installed. Specifying an explicit command allows native executables, Python scripts, or shell scripts with zero Node dependency.

2. Contract 1: agent-harness

Create ~/.cito/plugins/sample-agent/plugin.json and place your executable at bin/cito-plugin-sample-agent:

{
  "id": "sample-agent",
  "kind": "agent-harness",
  "displayName": "Sample Agent",
  "tier": "experimental",
  "sfSymbol": "terminal",
  "tint": "purple",
  "cliFlag": true,
  "command": ["./bin/cito-plugin-sample-agent"]
}

For each one-shot operation, Cito writes a single JSON line to stdin and closes stdin; the plugin writes a single JSON response line to stdout and exits. Requests include state_dir and env (except probe, which receives session_id, endpoint_pid, cwd, and state_dir; setup requests also include plugin_dir). Timeouts are 1.5s for discover_sessions and update_badge, 10s for setup_*, resolve_caller, and probe, and 120s for wake. Non-zero exits or invalid JSON produce PLUGIN_EXEC_FAILED.

OperationRequest / Response Contract
setup_inspectInspect installed configuration. Return {"ok":true,"installed":true,"configured":true,"paths":["..."]}.
setup_applyHonor dry_run and force. Return actions with target, path, status (created, updated, unchanged, or conflict), backupPath, and detail.
setup_removeHonor dry_run; remove only owned configuration and return actions.
discover_sessionsReturn {"ok":true,"sessions":[...]}. Each session carries harness, session_id, cwd, repo, branch, title, endpoint_pid, and updated_at_ms.
resolve_callerResolve meta, headers, cwd, http_client_pid, http_transport, require_open, cli_cmd, and explicit_session_id. Return {"ok":true,"caller":{...}} or {"ok":false,"error_code":"BINDING_REQUIRED","message":"..."}.
probeCheck session_id, cwd, and endpoint_pid. Return ok, status (alive, switched, closed_definitive, or transient_error), current_session_id, and reason.
update_badgeSet or clear badge for the session and endpoint. Return {"ok":true}.
wakeDeliver the rendered text and signals for batch_id; honor the wake flag. Return outcome: delivered, delivered_unconfirmed, session_switched, or driver_unavailable, plus ok and reason.
 
{"op":"wake","session_id":"session-1","cwd":"/Users/alice/repo","endpoint_pid":1234,"batch_id":"b_1","wake":true,"checkpoint_only":true,"queue_written":false,"queue_confirmed":false,"text":"Review needed","signals":[{"signal_id":"s_1","from_listener_id":"bob-8a4f2c9011b4e3d2","from_user":"bob","from_harness":"sample-agent","from_title":"Review","message":"Please review","created_at":"2026-09-01T00:00:00Z","in_reply_to":null}],"state_dir":"/Users/alice/.cito","env":{}}
{"ok":true,"outcome":"delivered","reason":null}

Single-step wake plugins can ignore checkpoint_only and return {"ok":true,"outcome":"delivered"} directly. Two-step wake plugins (which write to a local queue before triggering an external resume command) can return an intermediate checkpoint response with queue_written: true, queue_confirmed: true, and continue_wake: true, then complete the resume command on the follow-up invocation (returning open_confirmed: true or insertion_unknown: true when applicable).

Optional streaming sidecar

Set channelEnv to the environment variable that enables your streaming integration in cito mcp-stdio. When that variable is set, cito mcp-stdio spawns the plugin with {"op":"stdio_sidecar","endpoint_pid":1234,"cwd":"...","state_dir":"...","env":{}} and keeps stdin open. Emit {"op":"ready","capabilities_patch":{...}} first, then JSON-RPC notification frames on stdout. Monitor stdin for EOF and exit when the parent closes it.

3. Contract 2: human-channel

Hub-scoped human channels run as persistent subprocesses managed by the Hub. The Hub starts the subprocess when required Hub configuration is present or an on-demand pairing/test request arrives, and sends {"op":"shutdown"} when all bindings are disabled and Hub configuration is cleared. Monitor stdin on a dedicated reader thread and exit within 100 ms of EOF to prevent orphan polling processes. 

{
  "id": "sample-chat",
  "kind": "human-channel",
  "displayName": "Sample Chat",
  "tier": "experimental",
  "scope": "hub",
  "sfSymbol": "bubble.left.fill",
  "tint": "blue",
  "command": ["./bin/cito-plugin-sample-chat"],
  "fields": [
    { "key": "apiToken", "scope": "hub", "label": "API Token", "type": "secret", "required": true },
    { "key": "recipientId", "scope": "user", "label": "Recipient ID", "type": "string", "required": true }
  ],
  "pairing": { "supported": true, "actionLabel": "Pair Account…" }
}

Hub → plugin (stdin NDJSON)

  • configure: hub_config, bindings (each with principal_id, user, config), and persisted cursor.
  • deliver: delivery_id, principal_id, user, recipient config, and signal (signal_id, from with principal_id, user, host_id, host_name, harness, listener_id, title, and about, to.listener_id, message, in_reply_to, and created_at_ms).
  • on_acked: principal_id, signal_ids, acked_at_ms, external_msg_ids, and user_config, for synchronizing external read state.
  • format_pair / test: correlated RPC requests with req_id and hub_config. Pair formatting includes code; testing includes user and user_config.
  • pair_ack: code, ok, owner_user, and error. reply_ack: update_id, ok, signal_id, target_display, optional duplicate, and error.
  • {"op":"shutdown"}: release external connections and exit.
{"op":"configure","hub_config":{"apiToken":"example-token"},"bindings":[{"principal_id":"none#alice","user":"alice","config":{"recipientId":"room-1"}}],"cursor":"100"}
{"op":"deliver","delivery_id":"d_1","principal_id":"none#alice","user":"alice","config":{"recipientId":"room-1"},"signal":{"signal_id":"s_1","from":{"principal_id":"none#bob","user":"bob","host_id":"mac-1","host_name":"Bob-Mac","harness":"sample-agent","listener_id":"bob-8a4f2c9011b4e3d2","title":"Review","about":"Release check"},"to":{"listener_id":"c_9f0e1d2c3b4a5968"},"target_generation":1,"sender_endpoint_key":"ep_1","message":"Please review","in_reply_to":null,"created_at_ms":1700000000000}}

Plugin → Hub (stdout NDJSON)

  • delivered: report delivery_id, ok, external_msg_id, all external_msg_ids, and error after the external delivery result is known.
  • pair_redeem: provide code, external_chat_id, external_user_id, is_private_chat, display_label, and user_config_patch.
  • inbound_reply: provide update_id, external_chat_id, external_user_id, reply_to_external_msg_id, and text. The Hub resolves the reply target and routes a regular signal.
  • cursor_save: persist the channel's external update cursor after receiving reply_ack.
  • rpc_result: echo req_id, ok, and error; pair formatting returns instruction and optionally bot_username, while testing returns detail.
{"op":"delivered","delivery_id":"d_1","ok":true,"external_msg_id":"102","external_msg_ids":["101","102"],"error":null}
{"op":"inbound_reply","update_id":"u_99","external_chat_id":"room-1","external_user_id":"user-1","reply_to_external_msg_id":"102","text":"Ship it"}
{"op":"cursor_save","cursor":"101"}

Correlate delivery and RPC responses by their IDs. The Hub persists delivery mappings for reply resolution and read synchronization. If a subprocess exits with pending RPCs, callers receive {"ok":false,"error":"Plugin subprocess exited"}.

4. Configuration & Pairing

The Settings UI renders manifest fields automatically: fields[].scope: "hub" holds shared Hub credentials, while fields[].scope: "user" holds each user's recipient binding. With pairing.supported: true, the Hub generates a 10-character Base32 pairing token displayed with the cito- prefix: 

{"op":"format_pair","req_id":"r_1","code":"cito-a1b2c3d4e5","hub_config":{"apiToken":"example-token"}}
{"op":"rpc_result","req_id":"r_1","ok":true,"instruction":"Send /start cito-a1b2c3d4e5 in a private chat","error":null}
{"op":"pair_redeem","code":"cito-a1b2c3d4e5","external_chat_id":"room-1","external_user_id":"user-1","is_private_chat":true,"display_label":"alice","user_config_patch":{"recipientId":"room-1"}}
{"op":"pair_ack","code":"cito-a1b2c3d4e5","ok":true,"owner_user":"alice","error":null}

The Hub validates the pairing code and ownership before accepting the binding. Starting another pair, cancelling, or unpairing consumes old codes. Human replies and agent messages use the same Hub signaling path.

Agent manifests may provide postSetupHint and postDisconnectHint. Channel manifests may provide setupGuide (an array of instructions), fields[].configuredPlaceholder, fields[].helpText, and pairing.helpText. The Hub projects these as setup_guide, configured_placeholder, help_text, and pairing_help_text.

Field hidden is an access-control visibility flag: non-admin OIDC users cannot edit Hub-scoped fields. redacted independently suppresses secret values on the wire; configured reports whether a saved value exists. Omitted or blank configured secrets retain saved credentials unless an explicit clear/reset flag is provided. A channel test request receives merged candidate values without persisting them. Handle changed credentials or an empty cursor by resetting polling state; callbacks from a stopped process cannot outlive its shutdown.
