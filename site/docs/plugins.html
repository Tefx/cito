Plugin SDK Authoring Guide

Cito's core engine, daemon, and macOS UI contain zero hardcoded agent or messaging channel names. Every concrete coding harness (plugins/pi, plugins/codex, plugins/claude) and every human notification channel (plugins/human, plugins/telegram) is implemented against @tefx/cito/plugin-sdk and rendered dynamically from its plugin.json manifest.

1. Plugin Discovery & Directory Layout

Cito loads built-in plugins from plugins/<id>/ and user-installed plugins from ~/.cito/plugins/<id>/ (or any directory listed in CITO_PLUGIN_PATH). Each plugin directory contains:

  • plugin.json — declarative metadata, visual SF Symbol icon and tint, and optional two-scope configuration fields.
  • index.ts or index.js — default export implementing either HarnessAdapter (kind: "agent") or HumanChannelPlugin (kind: "human").

2. Authoring an Agent App Plugin (kind: "agent")

An Agent App plugin integrates a coding agent CLI or desktop IDE with Cito's session discovery, liveness probing, and wake delivery pipeline.

Step 1: Create ~/.cito/plugins/cursor/plugin.json

{
  "id": "cursor",
  "kind": "agent",
  "displayName": "Cursor",
  "tier": "custom",
  "sfSymbol": "cursorarrow.rays",
  "tint": "purple",
  "cliFlag": true
}

Step 2: Implement HarnessAdapter in index.ts

import type {
  HarnessAdapter,
  AvailableSessionSummary,
  ProbeOutcome,
  DeliverOutcome,
  DeliverContext,
} from "@tefx/cito/plugin-sdk";

const cursorAdapter: HarnessAdapter = {
  id: "cursor",
  pidKeys: ["cursor_pid", "caller_pid"],

  async discoverAvailableSessions(config, signal): Promise<AvailableSessionSummary[]> {
    // Return open local sessions so they appear under AVAILABLE SESSIONS in the menu bar UI
    return [];
  },

  async probe(row, config, signal): Promise<ProbeOutcome> {
    // Verify whether the enrolled session is still alive on this host
    return { status: "alive" };
  },

  async deliver(row, ctx: DeliverContext): Promise<DeliverOutcome> {
    // Deliver ctx.card (<cito_signal>...</cito_signal>) to wake the target session
    ctx.markQueueWritten();
    return "delivered";
  },
};

export default cursorAdapter;

3. Authoring a Human Channel Plugin (kind: "human")

A Human Channel plugin connects a user's Human Node (harness: "human", session_id: "default") to an external messaging surface (such as Telegram, Slack, Discord, or Webhook) with restart-idempotent delivery tracking and bidirectional reply routing.

Step 1: Declare Two-Scope Fields (scope: "hub" | "user") & Pairing in plugin.json

Fields in plugin.json support two scopes that the macOS SettingsPanel (Human Channels tab) renders automatically:

  • scope: "hub": Shared Hub-wide credentials (for example, a shared team Bot Token run by cito hub).
  • scope: "user": Per-user recipient binding (for example, each engineer's personal chatId or user handle).
{
  "id": "telegram",
  "kind": "human",
  "displayName": "Telegram",
  "tier": "stable",
  "sfSymbol": "paperplane.fill",
  "tint": "blue",
  "fields": [
    {
      "key": "botToken",
      "scope": "hub",
      "label": "Bot Token (@BotFather)",
      "type": "secret",
      "required": true,
      "placeholder": "123456789:AAH..."
    },
    {
      "key": "chatId",
      "scope": "user",
      "label": "Telegram Chat ID",
      "type": "string",
      "required": true,
      "placeholder": "Paired via /start code or enter manually"
    }
  ],
  "pairing": {
    "supported": true,
    "actionLabel": "Pair with Telegram"
  }
}

Step 2: Implement HumanChannelPlugin in index.ts

When pairing.supported is true, clicking the pairing button in Settings… generates a 6-character Base32 code (cito-xxxxxx). Your background service can complete pairing via ctx.completePairing(code, { userConfig }) and route human replies back to agents via ctx.resolveReplyTarget and ctx.sendReplyFromHuman: 

import type {
  HumanChannelPlugin,
  HumanNotificationPayload,
  HumanChannelDeliveryResult,
  HumanChannelServiceContext,
} from "@tefx/cito/plugin-sdk";

const customHumanPlugin: HumanChannelPlugin = {
  id: "custom-chat",
  kind: "human",

  formatPairingInstruction({ code }) {
    return `Send "/start cito-${code}" to your bot to link your account.`;
  },

  async testConnection({ hubConfig, userConfig, owner_user }) {
    return { ok: true, detail: `Verified channel for @${owner_user}` };
  },

  async sendNotification(
    notification: HumanNotificationPayload,
    { hubConfig, userConfig },
  ): Promise<HumanChannelDeliveryResult> {
    // Deliver notification.message to external channel and return externalMessageId for swipe-reply correlation
    return {
      delivered: true,
      externalMessageId: `msg-${notification.seq}`,
    };
  },

  async startService(ctx: HumanChannelServiceContext) {
    // Optional long-polling or webhook listener that calls:
    // 1. ctx.completePairing(code, { userConfig: { chatId } })
    // 2. ctx.resolveReplyTarget(principalId, { replyToExternalMsgId })
    // 3. ctx.sendReplyFromHuman(principalId, { to_listener_id, message, in_reply_to })
    return {
      async stop() {},
    };
  },
};

export default customHumanPlugin;
